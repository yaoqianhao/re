# M2 性能验收计划（D11 落地）

- 用途：把 `AI_ROADMAP §3.3` 项 7 判据「目标硬件稳定 60fps」变成**可复现、可跨机器对比**的验收口径，并提供后续其他硬件的测试计划
- 出处：`docs/m2/M2_DECISIONS.md` D11 拍板结论 —— 「默认（以当前开发机为准）+ 为后续其他硬件做测试也做计划」
- 生效范围：M2 全程；主用于 H05 收口，G04（帧尖峰）引用同一套打点与采样方法
- 日期：2026-11-20

## 1. 口径总则

1. **基准硬件 = 当前开发机**。本机跑出「通过」只代表基准硬件通过，**不等于** M2 性能全线达标。
2. 跨硬件结论只在 §6 矩阵对应行填实后给出；矩阵空行一律记为「未测」，不得用基准硬件结果代填。
3. 所有数字必须能被一条命令复现，采集命令行与输出文件随报告一并入库；禁止手抄帧率、禁止目测。
4. 性能判据**不进** `cargo xtask verify` 的 11 步（硬件相关、耗时长），由 H05 单独跑并留证；G04 的 `<2ms` 帧尖峰判据例外，它走 headless 打点，可进测试。

---

## 2. 指标定义

| 指标 | 定义 | 用途 |
|---|---|---|
| 帧时间 p50 | 采样窗口内帧时间的第 50 百分位 | 反映常态流畅度 |
| 帧时间 p95 | 第 95 百分位 | 反映可感知卡顿 |
| **帧时间 p99** | 第 99 百分位 | **主判据**：稳定 60fps 等价于 p99 ≤ 16.6ms |
| 单帧最大 | 采样窗口内最大帧时间 | 记录用，不单独设阈值；>33ms（低于 30fps）出现次数必须一并报告 |
| 掉帧计数 | 帧时间 >16.6ms 的帧数占比 | 辅助读数 |

「稳定 60fps」在本计划里**只有一个含义**：60 秒采样、预热 5 秒后、p99 帧时间 ≤ 16.6ms。其余任何表述（平均帧率、最高帧率）不作为通过依据。

| 项 | 设定 |
|---|---|

| 分辨率 | 1920×1080 窗口模式，垂直同步关闭（否则测的是 vsync 不是引擎） |
| 视角 | 第三人称，固定 FOV；不得为跑分调低画质档 |

## 4. 采样方法

1. 一条命令出报告（脚本随 H05 入库，不得是手敲的一次性命令）：
   - 命令需同时输出：环境信息（CPU / GPU / 内存 / 驱动 / OS 版本 / 构建配置）、per-frame 原始帧时间序列、汇总统计。
2. 预热 5 秒丢弃，随后 60 秒采样；采样期间不做编译、不并行跑测试、不开录屏。
3. 打点位置固定在帧循环尾部（swap 之前），与 G04 的 headless 打点**同一个插桩点**，避免两套口径。
4. 至少跑 **3 次**，取 3 次中 p99 最差的一次作为结论值（不是最好的一次）。
5. 原始帧时间序列以 JSON 或 CSV 落盘，随报告归档，便于后续复算。

## 5. 留证格式（H05 必须产出）

| 产出 | 内容 |
|---|---|
| `profile` 文件 | 至少 1 份 CPU 侧 trace（形状：单圈完整采样），可选叠加 GPU 侧 |
| 性能报告 | 一张表：场景设定 / 构建配置（是否 rapier 默认、是否 debug-assertions）/ 三次采样的 p50·p95·p99·单帧最大 / 结论 |
| 环境信息 | CPU / GPU / 内存 / 驱动版本 / OS 版本 / 引擎 commit |
| 原始数据 | 3 次采样的帧时间序列文件 |

结论栏只允许写「通过 / 不通过 / 未测」三选一，并注明适用硬件（基准机 / 矩阵中的具体机型）。
